# 2026.244.0617 — fix(command): apply the step env: modifier to the executed command

## Summary

The step-level `env:` modifier (a base #Op field, `spec/schema/_common.cue`) was schema-declared but never wired: the `command` verb ran the command with the container's default env, so an env-scoped probe (e.g. `OMARCHY_PATH=/tmp/missing-omarchy`) silently tested the wrong configuration. RCA: no executor path read `op.Env` — the command plugin's `RunVerb` called `cc.Exec().RunCapture(ctx, script)` with no env, and the runner's `EffectiveEnv` (variable expansion) excludes `op.Env`.

Fix: prepend the step env as shell exports (sorted keys, `spec/shellquote` quoting) to the command for the in-container, host-side, and background legs.
